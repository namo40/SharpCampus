저장소를 받은 직후의 개발 흐름입니다. 서버 코드는 전부 `dotnet run`으로 실행하므로 수정·재시작이 가장 빠릅니다. 끝나면 로컬에서 봇을 상대로 한 판 플레이하게 됩니다.

## 1. 인증과 데이터베이스 올리기

계정은 Supabase Auth가 맡습니다. 로컬 스택을 먼저 올립니다. Postgres와 인증 API가 Docker로 뜨고, 서버와 클라이언트는 이 스택이 출력하는 로컬 데모 키에 이미 맞춰져 있습니다.

```bash
supabase start
```

매치메이킹 큐와 방 레지스트리는 Redis에 저장됩니다. Supabase 스택에는 Redis가 없으므로 별도로 하나 띄웁니다.

```bash
docker run -d --name sharpcampus-redis -p 6379:6379 redis:8
```

프로필과 매치 기록은 같은 Postgres 안의 게임 전용 테이블에 저장됩니다. 스키마는 단일 파일 <SourceLink path="deploy/db/schema.sql" />이고, 테이블을 지우고 다시 만들기 때문에 같은 명령을 다시 실행하는 것이 곧 DB 초기화입니다.

<Tabs>
  <TabItem label="PowerShell">
    ```powershell
    Get-Content deploy/db/schema.sql | docker exec -i supabase_db_SharpCampus psql -U postgres -d postgres
    ```
  </TabItem>
  <TabItem label="POSIX 셸">
    ```bash
    docker exec -i supabase_db_SharpCampus psql -U postgres -d postgres < deploy/db/schema.sql
    ```
  </TabItem>
</Tabs>

## 2. 게임 밸런스는 masterdata/

틱 레이트, 중력 커브, 공격·콤보 테이블, 보상과 레이팅 상수, 스킨과 미션까지 게임 수치는 전부 `masterdata/` 폴더의 JSON입니다 (예: <SourceLink path="masterdata/game_config.json" />). 서버가 시작할 때 이 파일들을 읽으므로, 값을 수정하고 재시작하는 것만으로 밸런스 패치가 됩니다. 컨테이너 이미지에 넣을 데이터베이스로 컴파일하는 도구도 있지만 로컬 실행에는 필요 없습니다.

## 3. 서버 3개 실행

터미널 3개에 하나씩 띄웁니다.

```bash
dotnet run --project src/SharpCampus.ApiServer
```

```bash
dotnet run --project src/SharpCampus.RoomServer
```

```bash
dotnet run --project src/SharpCampus.BotServer
```

- **ApiServer**: 계정 확인, 프로필, 상점·미션, 매치메이킹. 클라이언트가 처음 접속하는 곳입니다.
- **RoomServer**: 매치 하나가 방 하나. 서버 권위 틱 루프로 게임을 시뮬레이션합니다.
- **BotServer**: 큐에서 오래 기다리는 사람이 생기면 봇을 로그인시켜 같은 큐로 보냅니다.

각 서버는 클라이언트용 gRPC 포트 옆에 운영용 HTTP 포트를 하나씩 엽니다 (5011·5012·5013). `/healthz`는 프로세스가 살아 있는 한 응답하고, `/readyz`는 Redis·Postgres 연결까지 확인하며, `/metrics`는 Prometheus 스크레이프입니다.

## 4. 첫 매치

게임 클라이언트는 터미널 전체를 씁니다.

```bash
dotnet run --project src/SharpCampus.Client
```

타이틀에서 **Play as guest**를 고르면 이메일 없이 바로 로비입니다. **Play a duel**로 큐에 들어가면 (Esc로 취소) 개발 설정 기준 15초쯤 뒤에 봇이 상대로 들어옵니다. 봇도 자기 계정으로 로그인해 같은 3회의 호출로 큐에 들어오므로, 서버 입장에서는 그저 또 하나의 클라이언트일 뿐입니다.

| 키 | 동작 |
| --- | --- |
| ← / → | 이동 |
| ↓ | 소프트 드롭 |
| Z / X | 회전 |
| Space | 하드 드롭 |
| C | 홀드 |
| Q | 기권 |

매치가 끝나면 코인과 레이팅이 정산되고, 리매치 제안에 답하면 로비로 돌아옵니다.

## 5. REPL로 서버 API 둘러보기

또 하나의 클라이언트 `SharpCampus.Cli`는 게임이 하는 모든 서버 호출을 명령 하나씩으로 노출하는 REPL입니다. 게임 클라이언트가 내부에서 어떤 호출을 하는지 확인하고 싶을 때 사용합니다.

```bash
dotnet run --project src/SharpCampus.Cli
```

```text
cli> guest
cli> whoami
cli> nickname boardsweeper
cli> duel
cli> history
cli> rank
```

`guest`는 익명 로그인으로 세션 파일을 만들고, `whoami`는 그 토큰을 ApiServer에 보내 계정과 프로필을 받아옵니다. `duel`은 큐 참가부터 대전 화면까지 게임과 같은 경로를 그대로 따라갑니다. 명령 전체 목록은 `help`로 볼 수 있습니다.

## 6. 정리

```bash
supabase stop
docker rm -f sharpcampus-redis
```
