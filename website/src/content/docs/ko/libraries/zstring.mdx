ZString은 문자열 조립의 중간 할당을 없애는 Cysharp 라이브러리입니다. `ArrayPool`에서 빌린 버퍼 위에 쌓는 struct 빌더와, 임시 문자열 없이 인자들을 이어 붙이는 `Concat`·`Format`을 제공합니다. 이 프로젝트에서는 콘솔 클라이언트의 보드 렌더러가 주 사용처입니다. 버전은 2.6.0입니다.

- GitHub: [Cysharp/ZString](https://github.com/Cysharp/ZString)

## 왜 쓰나

콘솔 클라이언트는 서버 델타가 올 때마다 두 보드, HUD, 키 안내까지 화면 전체를 문자열 한 덩어리로 조립해 초당 20번 다시 그립니다. 셀 하나 이어 붙일 때마다 `+`나 보간으로 임시 문자열을 만들면 매 프레임 수백 개의 짧은 가비지가 생기고, 그 수거가 프레임 사이의 미세한 멈춤으로 나타납니다. ZString의 빌더는 풀에서 빌린 버퍼에 쓰기만 하다가 마지막 `ToString()` 한 번만 할당하므로, 프레임당 할당이 결과 문자열 하나로 줄어듭니다.

참고로 서버 쪽 로깅이 같은 기법 위에 서 있습니다. ZLogger가 ZString의 포매팅 엔진 계열을 쓰는 이야기는 [ZLogger 페이지](../zlogger/)에서 다룹니다.

## 프레임 조립: struct 빌더

렌더러는 프레임마다 빌더 하나를 만들어 화면 전체를 쌓습니다.

```csharp
        // The builder is a mutable struct passed by ref, which rules out a using declaration.
        var frame = ZString.CreateStringBuilder();
        try
        {
            AppendHeader(ref frame, Strings.BoardHeaderYou, displayNames[seat]);
```

<SourceLink path="src/SharpCampus.Client.Common/Duel/DuelRenderer.cs" />

`CreateStringBuilder()`가 돌려주는 `Utf16ValueStringBuilder`는 클래스가 아니라 **mutable struct**입니다. 복사되는 순간 서로 다른 버퍼 상태 두 개가 생기므로, 조립을 나눠 맡는 내부 메서드들에 전부 `ref`로 넘깁니다. 그런데 `using var`로 선언한 변수는 읽기 전용이라 `ref`로 넘길 수 없어서, using 선언 대신 try/finally로 직접 반납합니다.

```csharp
            return frame.ToString();
        }
        finally
        {
            frame.Dispose();
        }
```

<SourceLink path="src/SharpCampus.Client.Common/Duel/DuelRenderer.cs" />

`Dispose()`가 빌린 버퍼를 풀에 돌려주는 반납 지점입니다. 조립을 맡는 메서드들의 시그니처는 이렇게 생겼습니다.

```csharp
    // A color code goes in only where the color changes, which keeps a frame from carrying one per cell.
    private static void AppendCell(ref Utf16ValueStringBuilder frame, ref string painted, string color, string glyph)
    {
        if (painted != color)
        {
            frame.Append(color.Length > 0 ? color : Reset);
            painted = color;
        }

        frame.Append(glyph);
    }
```

<SourceLink path="src/SharpCampus.Client.Common/Duel/DuelRenderer.cs" />

보드 두 개의 셀 400개가 초당 20회 지나가는 가장 뜨거운 경로인데, `Append`는 버퍼에 쓰기만 하니 이 안에서는 할당이 없습니다. 프레임을 통짜로 조립해 한 번에 출력하는 설계(이전 프레임 위에 덮어쓰기)와 합쳐져, 화면의 두 보드는 항상 같은 틱에 속하고 그리기 비용은 문자열 하나 값입니다.

## 단발 이어 붙이기: Concat

빌더를 세울 정도가 아닌 자리는 `ZString.Concat`이 맡습니다. 완성된 프레임을 커서 복귀 시퀀스·공지와 함께 내보내는 출력 지점이 하나이고,

```csharp
    private void Draw()
    {
        var frame = receiver.Read(renderer, static (r, replica) => r.BuildFrame(replica));
        Console.Out.Write(ZString.Concat(CursorHome, frame, _notice));
    }
```

<SourceLink path="src/SharpCampus.Client.Common/Duel/DuelSession.cs" />

리매치 대기의 카운트다운 프롬프트가 또 하나입니다. 1초마다 같은 줄을 다시 쓰는 자리라, 역시 임시 문자열 없이 이어 붙입니다.

```csharp
                Console.Out.Write(ZString.Concat("\r", Localization.Format(CommonStrings.RematchPrompt, remaining), "   "));
```

<SourceLink path="src/SharpCampus.Client/Duel/DuelFlow.cs" />

`Concat`은 인자들을 내부 버퍼에 차례로 포맷한 뒤 결과 문자열 하나만 만듭니다. `string.Concat`과 다른 점은 인자가 `int` 같은 값 타입이어도 박싱과 중간 `ToString()` 없이 버퍼에 직접 쓴다는 것입니다.
